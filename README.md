# 窓口・庁内問い合わせ 回答標準化ツール

公開URL：https://takashi-101.github.io/madoguchi-kaito/

「設定・データ」の「見本データを読み込む」を押すと、架空の町の台帳と文書で使い方を確かめられます。

## 何の道具か

窓口・電話・庁内問い合わせに対応する職員が、事務マニュアルや例規（条例・規則・要綱）の原文を根拠にして、誰が答えても同じ回答になるようにするための道具です。

- 問い合わせの分類ごとに、標準回答と根拠（文書名・章・ページ）を **標準回答台帳** にまとめます。
- マニュアル・例規のファイルを取り込み、語句で **全文検索** します。当てはまる箇所はすべて、原文と文書名・章（見出し）・ページを並べて表示します。
- 問い合わせの内容を入れると、台帳の標準回答と原文の該当箇所を並べ、回答を組み立てられます。
- 同じ小分類に内容の違う標準回答があるときは「回答がばらついています」、根拠がない・原文に見つからないときは「根拠がありません」「根拠が原文に見つかりません」の印を付けます。
- このPCの中で動くAI（Ollama）があれば、選んだ原文だけを材料に回答の下書き候補を作れます。下書きの横に材料の原文を並べ、原文にない語句（金額・日付・窓口名・電話番号など）に印を付けます。下書きは候補で、確定するのは職員です。
- 台帳を分類ごとの「窓口対応 標準回答集」としてA4で印刷できます。

## 誰が何に使うか

| 使う人 | 使い方 |
|---|---|
| 窓口・電話の担当職員 | 「回答の作成」で問い合わせを入れ、標準回答と原文を見て答える |
| 各係の担当 | 「標準回答台帳」で、自分の係の標準回答と根拠を登録・更新する |
| 係長・庶務担当 | 印の付いた標準回答（ばらつき・根拠なし）を見直し、「標準回答集」を印刷して配る |

## 画面

| 画面 | できること |
|---|---|
| 回答の作成 | 問い合わせから、台帳の標準回答と原文の該当箇所を並べる。回答を組み立て、台帳に登録する。AIの下書き候補を作る |
| 標準回答台帳 | 大分類・小分類、よくある問い合わせ、標準回答、根拠（文書名・章・条・ページ・該当文言）、担当の係、最終更新日の登録・修正・削除。語句・大分類・印での絞り込み |
| マニュアル・例規の検索 | テキスト（.txt）、HTML（.html）、文字を選べるPDF（.pdf）の取り込みと全文検索 |
| 標準回答集の印刷 | 分類ごとにまとめ、根拠と最終更新日を付けてA4で印刷 |
| 設定・データ | AIの接続、JSONの書き出し・読み込み（置き換え）・追加の取り込み、CSVの書き出し、見本データ、消去 |

### 表記の揺れ

検索では、次の違いを同じものとして扱います。

- 全角・半角（「３００円」と「300円」、「ｼﾞｭｳﾐﾝﾋｮｳ」と「ジュウミンヒョウ」）
- ひらがな・カタカナ（「じゅうみんひょう」と「ジュウミンヒョウ」）
- 送り仮名の一部（「申し込み」「申込み」「申込」、「取り扱い」「取扱い」「取扱」、「引っ越し」「引越し」、「受け付け」「受付」、「問い合わせ」「問合せ」など）
- 空白・改行（PDFの行の折り返しをまたいでも当たります）

### ばらつきと根拠の印

- **回答がばらついています**：同じ大分類・小分類に、内容の違う標準回答が2つ以上あるとき。句読点・空白だけの違い、漢数字と算用数字の違い（「三百円」と「300円」）は同じ内容として扱います。小分類は「一つの答えになる単位」（例：住民票の写し 手数料）で付けてください。
- **根拠がありません**：根拠の欄（文書名）が空のとき。
- **根拠が原文に見つかりません**：文書は取り込まれているが、指定した章・条・見出し、ページ、該当文言が原文の中に見つからないとき。
- **根拠の文書が未取り込み**：根拠の文書がまだ取り込まれておらず、原文の中にあるかを確かめられないとき。

## 動かし方

- **公開URLで使う**：上のURLをブラウザで開きます。
- **PCに置いて使う**：このリポジトリを「Code」→「Download ZIP」で取得して展開し、`index.html` をブラウザ（Microsoft Edge、Google Chrome など）で開きます。インストールもビルドも要りません。ネットにつながらないPCでも動きます。

必要な部品（PDFを読む pdf.js）はリポジトリの中に同梱しています。外部のサイトから部品・フォント・画像を読み込むことはありません。

## データがPCの外に出ないこと

- 台帳と、取り込んだマニュアル・例規の本文は、使っているブラウザの中（IndexedDB）にだけ保存します。外部には送りません。
- **問い合わせの内容の欄と回答欄の中身は保存しません。** 画面を閉じると消えます。閉じる前には確認が出ます。
- AIは、既定ではこのPCの中で動く Ollama（`http://localhost:11434`）につなぎます。外部のAPIは、「設定・データ」で使う人が選んだときだけ使い、送る前に毎回確認が出ます。外部のAPIの鍵は保存しません。
- ブラウザの保存は、PC・ブラウザごとに別です。他のPC・他の職員に渡すときは、「設定・データ」でJSONを書き出し、相手が読み込みます。
- ブラウザの閲覧履歴やサイトデータを消すと、保存した台帳と文書も消えます。定期的に「台帳と文書をまとめて書き出す（JSON）」で控えを取ってください。
- 個人名を入れる欄はありません。担当は係名（例：住民課 住民記録係）で表します。

## データの書き出し・読み込み

| 操作 | 内容 |
|---|---|
| 台帳を書き出す（JSON） | 台帳だけを書き出します |
| 台帳と文書をまとめて書き出す（JSON） | 台帳と取り込んだ文書の本文を書き出します |
| 台帳を書き出す（CSV・Excel用） | Excelでそのまま開ける形（BOM付きUTF-8）です。確認の印の列も付きます |
| 読み込む（置き換え） | 今の内容を、ファイルの内容で置き換えます |
| 追加で取り込む | 今の内容に足します。同じ内容のものは取り込まず、件数を表示します |

## AI（Ollama）の設定

AIを使わなくても、台帳・検索・回答の作成・印刷はすべて使えます。下書き候補を作るときだけ、次の設定をします。

1. Ollama（https://ollama.com/ ）をPCに入れ、モデルを入れます。例：

```bash
ollama pull gemma3:4b
```

2. ブラウザで開いたこのツールから Ollama につなげるよう、環境変数 `OLLAMA_ORIGINS` に、このツールを開く場所を設定します。

**Windows**（コマンドプロンプトで実行し、タスクトレイの Ollama を終了してから起動し直します）

公開URLで使うとき：

```bash
setx OLLAMA_ORIGINS "https://takashi-101.github.io"
```

`index.html` をファイルとして開いて使うとき（上の設定でつながらない場合）：

```bash
setx OLLAMA_ORIGINS "*"
```

**Mac**（ターミナルで実行し、Ollama を起動し直します）

```bash
launchctl setenv OLLAMA_ORIGINS "https://takashi-101.github.io"
```

3. このツールの「設定・データ」→「AIの接続」で「接続を確かめる」を押し、入っているモデルが表示されればつながっています。
4. 公開URLから使うとき、ブラウザが「ローカルネットワーク上のデバイスへのアクセス」の許可を求めることがあります。その場合は許可してください。

**ネットにつながったPCでは、使い終わったら `OLLAMA_ORIGINS` を元に戻してください。** 特に `"*"` は、どのWebサイトからでもこのPCの Ollama を呼び出せる状態になります。

Windows で元に戻す（設定を消す）：

```bash
reg delete HKCU\Environment /F /V OLLAMA_ORIGINS
```

Mac で元に戻す：

```bash
launchctl unsetenv OLLAMA_ORIGINS
```

元に戻したあとは、Ollama を起動し直してください。

下書き候補を作る時間は、PCの性能とモデルの大きさで変わります。メモリ16GBの事務用ノートPCでは、小さめのモデル（数B程度）を選んでください。

## 更新したあと、新しい版を開かせる方法（版の印）

`index.html` が読み込むCSS・JavaScriptのURLには、`?v=20261105-1` のような版の印を付けています。ファイルを直したら、印を新しい値に付け直してください。利用者は普通に開き直すだけで新しい版が表示されます。

付け直す場所：

- `index.html` の中のすべての `?v=…`
- `js/docparse.js` の `VERSION_MARK`（PDFを読む部品の読み込みに使います）

まとめて付け直すコマンド（例：`20261105-1` を `20261201-1` にする）。

Mac・Linux・Git Bash：

```bash
sed -i 's/20261105-1/20261201-1/g' index.html js/docparse.js
```

Windows PowerShell：

```bash
foreach ($f in 'index.html','js/docparse.js') { (Get-Content $f -Encoding UTF8) -replace '20261105-1','20261201-1' | Set-Content $f -Encoding UTF8 }
```

## 見本データ

架空の「見本町」の窓口を想定した見本です。実在の自治体・例規ではありません。

- 標準回答台帳 15件（窓口共通、証明書、住所の異動、電話対応、手数料、ごみ）
- 見本町 住民窓口事務取扱マニュアル（テキスト、4ページ）
- 見本町手数料条例（HTML）
- 見本町粗大ごみ収集受付要綱（PDF、2ページ）

台帳には、わざと次の2件を入れています。

- 回答がばらついているもの：「住民票の写し 手数料」に「1通300円」と「1通200円」の2つの回答
- 根拠のないもの：「粗大ごみ 家電」（根拠の欄が空）

同じ文書のファイルを `sample` フォルダに置いています。「マニュアル・例規の検索」に落として、取り込みの練習に使えます。

## テスト

`test` フォルダにテストがあります。Node.js と Playwright（Chromium）が入った環境で、次のコマンドで実行します。

```bash
node test/run-all.js
```

各テストは、GitHub Pages と同じ形（`/madoguchi-kaito/` の下に置いた静的配信）と、`index.html` をファイルとして開いた形の両方で確かめます。Ollama と外部のAPIは、応答の形をまねた仮の応答で確かめています。
